# Rudra Optical

A mobile-first, local optical store website — no cart, checkout, payment,
shipping, or online ordering. Runs on **Cloudflare Pages**: static pages in
`public/`, a small Postgres-backed backend as Cloudflare Pages Functions in
`functions/`.

> This project moved here from Vercel. Vercel's free Hobby plan prohibits
> commercial use in its Terms of Service — a real business site isn't
> allowed on it even without payments. Cloudflare's free tier has no such
> restriction; it's priced purely by usage (100,000 requests/day free).

## Start locally

1. Create a free project at [supabase.com](https://supabase.com) if you don't have one yet.
2. In the Supabase SQL editor, run [`database/app-state-schema.sql`](database/app-state-schema.sql), [`database/product-images-storage.sql`](database/product-images-storage.sql), and [`database/gallery-images-storage.sql`](database/gallery-images-storage.sql).
3. Copy `.env.example` to `.env` and fill in:
   - `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` — Project Settings -> API.
   - `SUPABASE_SERVICE_ROLE_KEY` — same page, the **secret** key. Server-only, never commit it.
4. Run `node scripts/hash-password.mjs "a strong admin password"` and paste the resulting `ADMIN_PASSWORD_HASH` line into `.env`. Add a long random `TOKEN_SECRET` too.
5. Install the Wrangler CLI once: `npm i -g wrangler`.
6. Run `npm run build`, then `wrangler pages dev public --compatibility-date=2026-01-01` to serve `public/` and the `functions/` together, the same way production does.

For a local-only shortcut you can set `ADMIN_PASSWORD` in `.env` instead of step 4 — but note the login check in `lib/http.js` only ever accepts `ADMIN_PASSWORD_HASH`; wire up a dev fallback there if you want one.

## Deploying

Import the repo in Cloudflare Pages (Workers & Pages -> Create -> Pages -> Connect to Git). Build command: `npm run build`. Build output directory: `public`. Then in the Pages project's **Settings -> Environment variables**, set: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_PASSWORD_HASH`, `TOKEN_SECRET`, and optionally `RESEND_API_KEY` / `EMAIL_FROM`.

**Important — password hash format changed.** This project used to run on Vercel/Node, where the admin password was hashed with Node's `scrypt`. Cloudflare Workers don't have that available, so passwords are now hashed with PBKDF2 via the Web Crypto API instead. Any `ADMIN_PASSWORD_HASH` generated by the old script will **not** work here — generate a new one with the updated `scripts/hash-password.mjs` and set it fresh in Cloudflare.

## What is configurable

- `public/config/store.js` is the central, safe-to-share source for the store name, contact details, hours, map link, homepage copy, product showcase, and services.
- Replace `public/assets/visiona-hero.png` and `public/assets/frame-collection.png` (hero banner + about/gallery imagery) with real photos — product and gallery photos themselves are handled entirely in `/admin`, no code change needed.
- Admin edits persist in Supabase (see the `database/` SQL files), so they survive redeploys.

## Connected workflows

- Inquiry, appointment-request, and review forms validate on the client and server, are rate-limited (persisted per IP in the `rate_limits` table), and save to Supabase.
- Reviews remain pending until an admin approves them.
- The admin area supports status updates, review moderation, product and gallery photo upload, service visibility, store info (including opening hours), and homepage copy — all editable without touching code.
- When `RESEND_API_KEY` and `EMAIL_FROM` are supplied, new submissions are emailed to the store address via Resend. Without those settings they're still safely stored and visible in the admin dashboard. Email sends and image cleanup use `context.waitUntil()` so they finish even after the response is sent — required on Cloudflare Workers, unlike a traditional Node server.

## Before launch

- [ ] Generate a fresh `ADMIN_PASSWORD_HASH` (see above — the old one won't work) and a real random `TOKEN_SECRET`.
- [ ] Replace the temporary business details in `public/config/store.js` — the `about.story` text especially.
- [ ] Replace `public/assets/visiona-hero.png` and `public/assets/frame-collection.png` with real photos.
- [ ] Configure `RESEND_API_KEY` / `EMAIL_FROM` so you actually get emailed when someone submits a form.
- [ ] Have the privacy and terms starter text checked for your local requirements.
